## 🚨 CRÍTICO

### A1. Rotas abertas por `authenticate()` sem verificação do retorno

`authenticate()` em `lib/middleware.ts:9` devolve `null` quando não há token — **nunca lança exceção**. Estas rotas chamam `await authenticate(request)` sem verificar o resultado e ficam **totalmente públicas**:

- [ ] `GET /api/seasons` — `app/api/seasons/route.ts:11`
- [ ] `GET /api/seasons/active` — `app/api/seasons/active/route.ts:11`
- [ ] `GET /api/seasons/[id]` — `app/api/seasons/[id]/route.ts:14`
- [ ] `GET /api/dinners` — `app/api/dinners/route.ts:10`

**Fix:** substituir por `requireAuth()` e devolver o `NextResponse` quando `auth instanceof NextResponse`. Considerar tornar `authenticate` privado ao módulo para impedir reutilização incorreta.

### A2. Rotas sem qualquer verificação de autenticação

- [ ] `GET /api/seasons/[id]/stats` — `app/api/seasons/[id]/stats/route.ts` — **expõe pagamentos e multas dos membros**
- [ ] `GET /api/dinners/[id]/ratings` — `app/api/dinners/[id]/ratings/route.ts` — expõe ratings e quem trouxe cada garrafa
- [ ] `GET /api/dinners/[id]/reveal-status` — `app/api/dinners/[id]/reveal-status/route.ts`

**Fix:** adicionar `requireAuth()` no início + validação UUID dos params (convenção do projeto).

### A3. PII commitado no git

- [ ] `scripts/season1-data.json` contém **emails reais de membros** (hotmail/gmail). Mesmo removendo o ficheiro, permanece no histórico. Se o repo for/vier a ser público, reescrever o histórico (`git filter-repo`) ou considerar os dados expostos.
